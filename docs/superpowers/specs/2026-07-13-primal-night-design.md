# PRIMAL NIGHT 게임 설계서

- 상태: 사용자 검토 대기
- 작성일: 2026-07-13
- 목표 플랫폼: Steam / Windows 10·11 x86_64
- 목표 개발 기간: 3~6개월
- 목표 가격: USD 7.99
- 목표 플레이 인원: 1~2인 온라인 협동
- 목표 플레이타임: 1회 60~120분, 첫 탈출까지 2~3시간

## 1. 제품 정의

### 1.1 한 문장 소개

현대인 조난자들이 시간 균열로 떨어진 가상의 공룡 시대에서 7일 동안 소리·냄새·부상을 관리하고, 화산 폭발 전에 구조 신호기를 완성해 탈출하는 2D 아이소메트릭 협동 생존 스릴러.

### 1.2 플레이어에게 주는 약속

1. 공룡은 플레이어만 쫓는 몬스터가 아니라 먹고, 도망치고, 사냥하고, 이동하는 생태계 구성원이다.
2. 강한 무기보다 관찰, 준비, 우회와 협동이 더 중요한 상황이 반복된다.
3. 한 판에는 명확한 시작과 끝이 있으며, 반복적인 자원 노동을 강요하지 않는다.
4. 작은 실수 하나가 연쇄적으로 위기를 만들지만, 플레이어가 원인을 이해하고 다음 판에 학습할 수 있다.

### 1.3 차별점

- 3D 공룡 액션이 아닌 2D 아이소메트릭 시스템 생존
- 좀비 무리 대신 상호작용하는 공룡 생태계
- 소음뿐 아니라 바람에 전달되는 냄새가 위험을 결정
- 현대 장비가 점차 소진되고 원시 제작으로 전환되는 성장 구조
- 무한 샌드박스가 아닌 7일 탈출형 세션

### 1.4 사실성과 세계관

인류와 비조류 공룡이 공존했다는 역사적 주장을 하지 않는다. 등장인물은 현대에서 시간 균열로 이동하며, 서로 다른 중생대 생물이 한 계곡에 나타나는 현상도 균열 때문에 발생한 가상 설정으로 설명한다.

상점명과 홍보물에서는 `Jurassic Park`, 로고, 고유 시설 디자인 등 타사 지식재산을 사용하지 않는다. `공룡 시대`, `선사 세계`, `시간 균열`처럼 일반적인 표현만 사용한다.

## 2. 목표와 제외 범위

### 2.1 출시 목표

- 처음 플레이한 두 사람이 별도 공략 없이 기본 생존과 탈출 목표를 이해한다.
- 한 세션이 120분을 넘기기 전에 성공 또는 의미 있는 실패로 끝난다.
- 혼자서도 전체 콘텐츠를 완료할 수 있고, 2인 플레이에서는 역할 분담이 자연스럽게 발생한다.
- 같은 맵에서도 자원, 날씨, 공룡 이동과 사건 조합이 달라 최소 3회의 재도전 가치를 제공한다.
- 저사양 Windows PC에서 1080p 60fps를 목표로 한다.

### 2.2 출시 버전 비목표

다음 항목은 출시 버전에서 구현하지 않는다.

- 무한 또는 대규모 절차 생성 오픈월드
- 3~4인 플레이, 전용 서버, 서버 브라우저, 호스트 이전
- PvP, 경쟁 랭킹, 안티치트 시스템
- 게임 내 음성 채팅 또는 음성 인식 퍼즐
- 공룡 길들이기, 탑승, 교배와 유전
- 자유형 건축, 농사, 부족 운영, NPC 외교
- 계절 변화와 장기 문명 발전
- Steam Workshop 및 공식 모드 도구
- 콘솔·모바일·macOS·Linux 동시 출시
- 실시간 유체, 복잡한 파괴 물리, 수백 개 동시 개체

이 항목들은 코드에 빈 버튼이나 완료된 것처럼 보이는 주석으로 남기지 않는다. UI와 상점 페이지에도 출시 기능으로 표시하지 않는다.

## 3. 대상 사용자와 경험 원칙

### 3.1 대상 사용자

- 《Project Zomboid》의 신중한 생존과 사망 서사를 좋아하는 사용자
- 친구 한 명과 짧고 강한 협동 생존 경험을 원하는 사용자
- 공룡을 처치 대상보다 예측하기 어려운 동물로 만나고 싶은 사용자
- 스트리머의 계획, 실수, 구조와 배신 아닌 돌발 상황을 구경하는 시청자

### 3.2 경험 원칙

#### 진지한 세계, 자연스럽게 발생하는 이야기

게임이 농담을 강요하지 않는다. 웃긴 장면이 생기더라도 친구가 피 묻은 고기를 기지로 가져오거나, 공포에 질려 잘못 던진 창처럼 시스템의 결과여야 한다.

#### 정보가 부족해도 불공정하지 않게

공격 전에는 발자국, 울음, 풀의 움직임, 새의 비행, 화면 진동 중 최소 하나를 제공한다. 플레이어가 인지할 수 없는 즉사 공격은 허용하지 않는다.

#### 싸움보다 생존

대형 포식자는 일반 장비로 정면 처치할 수 없다. 불, 미끼, 지형, 함정과 우회가 기본 해법이다.

#### 실패 원인의 가시성

사망 화면에는 마지막 피해만 표시하지 않는다. `출혈 → 바람을 탄 냄새 → 랩터 조사 → 추격 중 골절`처럼 최근 위험 연쇄를 간략하게 보여준다.

## 4. 세션 구조

### 4.1 한 판의 흐름

1. 시간 균열 추락 지점에서 최소 현대 장비를 회수한다.
2. 물과 임시 은신처를 확보한다.
3. 세 지역을 탐험해 구조 신호기 부품 3개를 찾는다.
4. 날씨와 공룡 이동에 맞춰 장비, 식량, 치료제를 준비한다.
5. 7일 차 화산 분화 전에 능선의 신호기를 가동한다.
6. 신호기가 충전되는 90초 동안 위치를 방어하거나 포식자를 유인한다.
7. 균열이 열리면 남은 시간 안에 살아 있는 플레이어가 탈출한다.

7일 차에는 별도의 하드 마감이 적용된다.

- 7일 차 시작 후 8분: 신호기 가동 상호작용 완료 가능 시간 종료
- 가동 후 90초: 충전 완료 및 균열 개방
- 7일 차 시작 후 10분: 화쇄류가 계곡에 도달하고 세션 즉시 종료
- 8분 이전에 가동했더라도 10분까지 균열에 들어가지 못한 플레이어는 탈출 실패
- 신호기를 일찍 가동하면 충전 완료 후 남은 시간만큼 균열이 열린 상태로 유지

따라서 가동 상호작용을 7일 차 8분 이전에 시작했더라도 8분까지 완료하지 못하면 가동에 실패한다. 기본 90초 충전의 탈출 여유는 30초이며, 75초 충전 업그레이드를 적용하면 45초다. UI는 7일 차 내내 가동 완료 마감과 계곡 붕괴 마감을 서로 다른 타이머로 표시한다.

### 4.2 하루 길이와 압박

- 게임 내 하루: 기본 10분
- 낮: 7분
- 황혼: 1분
- 밤: 2분
- 설정에 따라 전체 속도 0.75배, 1배, 1.25배 제공
- 인벤토리와 제작 화면은 싱글플레이에서만 일시정지

### 4.3 일자별 변화

| 일자 | 주요 변화 | 플레이어 목표 |
|---|---|---|
| 1일 | 온화한 날씨, 소형 생물 중심 | 물, 불, 임시 거점 확보 |
| 2일 | 첫 육식 공룡 이동 | 돌창과 치료 도구 제작 |
| 3일 | 강우 가능, 강 수위 상승 | 첫 신호기 부품 회수 |
| 4일 | 초식 공룡 대이동 | 이동로를 이용하거나 피하기 |
| 5일 | 랩터 무리 활동 증가 | 나머지 부품과 식량 확보 |
| 6일 | 화산재, 시야 저하 | 능선 이동과 최종 준비 |
| 7일 | 분화, 대형 포식자 이동 | 신호기 가동과 탈출 |

## 5. 핵심 시스템

### 5.1 생존 수치

출시 버전은 과도한 계기판을 피하고 다음 네 가지를 사용한다.

- 체온: 비, 밤, 불, 의복의 영향을 받음
- 수분: 강, 빗물, 과일로 회복하며 오염된 물은 질병 위험이 있음
- 포만: 행동 효율과 체력 회복에 영향
- 피로: 달리기, 전투, 운반과 수면에 영향

수치가 낮아졌다는 이유만으로 즉시 사망시키지 않는다. 먼저 이동, 회복, 조준과 체온 유지 능력이 단계적으로 악화된다.

### 5.2 부상과 치료

신체 부위는 머리, 몸통, 팔, 다리 네 영역으로 제한한다.

| 상태 | 효과 | 기본 치료 |
|---|---|---|
| 출혈 | 흔적과 냄새 생성, 지속 피해 | 압박 붕대 |
| 열상 | 제작·공격 또는 이동 효율 감소 | 세척 후 붕대 |
| 골절 | 팔 사용 또는 달리기 제한 | 부목과 휴식 |
| 감염 | 발열, 체력 회복 감소 | 소독·약초 치료 |
| 저체온 | 행동과 반응 속도 감소 | 불, 마른 옷, 수면 |
| 공황 | 시야와 조준 안정성 감소 | 안전지대, 동료 근접 |

동료는 상호작용을 길게 눌러 출혈을 압박하거나 부축할 수 있다. 치료 중에는 두 플레이어 모두 이동과 공격이 제한된다.

### 5.3 소리 시스템

각 행동은 데이터로 정의된 소리 반경과 지속 시간을 가진다.

- 걷기, 달리기, 수풀 통과
- 나무와 돌 채집
- 창 투척과 함정 작동
- 총격, 조명탄, 폭발
- 플레이어의 부상 신음
- 공룡 울음과 싸움

지형과 벽은 소리를 감쇠한다. 공룡은 정확한 좌표를 즉시 알지 못하고, 마지막으로 들은 위치를 조사한다.

### 5.4 냄새와 바람 시스템

맵을 저해상도 냄새 격자로 나누고, 다음 원천이 냄새값을 생성한다.

- 출혈 중인 생물
- 날고기와 조리 중인 음식
- 시체와 배설물
- 피 묻은 옷과 장비
- 특정 식물과 미끼

냄새는 바람 방향으로 이동하면서 시간에 따라 감소한다. 화면에는 정확한 수치 대신 바람 화살표, 캐릭터 반응과 공룡의 행동으로 전달한다. 디버그 빌드에서는 격자와 농도를 시각화해 실제 전파 여부를 검증한다.

### 5.5 공룡 생태계

출시 버전은 역할이 겹치지 않는 5종으로 제한한다.

| 역할 | 가칭 | 핵심 행동 |
|---|---|---|
| 소형 청소동물 | 스캐빈저 | 음식 절도, 시체 추적, 위험 지역 유도 |
| 무리 포식자 | 랩터 | 고립된 대상 우선, 측면 포위, 불 회피 |
| 중형 초식동물 | 혼드 허브 | 둥지 방어, 돌진, 경계 울음 |
| 대형 초식동물 | 헤비 허드 | 무리 이동, 장애물 파괴, 포식자 회피 |
| 최상위 포식자 | 에이펙스 | 소리·냄새 조사, 다른 공룡 사냥, 후반 이동 |

각 개체의 상태는 `배회 → 먹이/물 탐색 → 감지 → 조사 → 경계 → 추격/도주 → 섭식 → 휴식`으로 구성한다. 모든 공룡에게 모든 상태를 강제하지 않고 종별 행동 데이터로 조합한다.

공룡끼리도 감지와 공격이 발생한다. 단, 화면 밖 전체 생태계를 고정밀 시뮬레이션하지 않는다. 플레이어 주변 활성 구역만 완전한 AI로 실행하고 먼 구역은 개체 수, 목적지와 도착 시간만 계산한다.

### 5.6 전투와 은신

- 근접: 돌칼, 곤봉, 창
- 원거리: 투창, 제한된 권총, 조명탄
- 방어: 횃불, 연막성 식물, 가시 함정, 미끼
- 은신: 웅크리기, 수풀, 바위 엄폐, 냄새 세척

명중 판정은 서버 권한으로 처리한다. 공격 애니메이션, 사거리와 피격 영역을 데이터화하고 디버그 표시를 제공한다. 무기 설명에 표시된 피해·소음·스태미나 값은 실제 데이터에서 생성해 설명과 구현이 어긋나지 않게 한다.

### 5.7 현대 장비의 소진

현대 장비는 강하지만 재생 불가능한 자원이다.

- 스마트폰: 손전등 또는 녹음된 소리 재생, 배터리 한정
- 라이터: 즉시 점화, 연료 한정
- 구급상자: 빠른 치료 2~3회
- 접이식 칼: 높은 초반 제작 효율, 수리 불가
- 권총: 총알 3발, 매우 큰 소음
- 조명탄: 구조 신호기 또는 포식자 유인에 사용

현대 장비를 분해하면 필수 신호기 부품이 아니라 `전자 부속`을 얻는다. 전자 부속은 다음과 같은 선택형 신호기 보정에만 사용한다.

- 충전 소음 반경 30% 감소
- 충전 시간 90초에서 75초로 단축
- 가동 상호작용 시간 5초에서 2초로 단축

세 지역에서 회수하는 신호기 부품 3개는 다른 아이템으로 대체할 수 없으며, 부품을 모두 회수해야 최종 신호기를 가동할 수 있다. 현대 장비 분해는 핵심 탐험을 건너뛰게 하지 않고 최종 탈출의 위험만 낮춘다.

### 5.8 수집, 인벤토리와 제작

- 인벤토리: 기본 16칸과 무게 제한
- 장비 슬롯: 손 2개, 몸, 등, 도구 벨트
- 제작법: 출시 시 최대 20개
- 자원 종류: 출시 시 최대 18개
- 바닥의 동일 자원은 묶어서 표시
- 자주 쓰는 붕대, 횃불, 창은 퀵 제작 제공

자유 건축 대신 지정 범위에 스냅되는 생존 설비만 제공한다.

- 모닥불
- 건조대
- 저장 바구니
- 침낭
- 가시 장애물
- 빗물받이

### 5.9 사망과 복귀

- 쓰러짐: 치명상 시 60초 구조 시간
- 구조: 동료가 출혈을 멈추고 안전한 곳으로 끌 수 있음
- 사망: 시체, 가방과 장비가 세계에 남음
- 싱글플레이: 사망 시 해당 세션 종료
- 협동: 1~4일 차 사망자는 다음 새벽 새 조난자로 세션당 1회 복귀 가능
- 5~7일 차: 추가 조난자가 도착하지 않아 사망자는 관전만 가능

복귀 규칙은 친구가 초반 실수로 1시간 동안 게임에서 배제되는 문제를 방지하면서도 사망의 손실을 유지한다.

## 6. 맵과 콘텐츠 범위

### 6.1 맵

단일 계곡 맵을 다음 5개 구역으로 구성한다.

1. 추락 지점: 튜토리얼과 초기 현대 장비
2. 강변: 물, 약초, 범람 위험
3. 밀림: 시야 제한, 랩터, 풍부한 자원
4. 둥지 평원: 초식 공룡 무리와 신호기 부품
5. 화산 능선: 최종 신호기와 탈출 지점

맵 지형은 고정하되 자원 군집, 시체, 일부 길막, 공룡 둥지와 날씨 순서를 시드에 따라 변화시킨다. 플레이어가 길을 학습할 수 있으면서 매 판 위험 배치가 달라진다.

### 6.2 목표 콘텐츠 수

- 플레이어 캐릭터 외형: 기본 4종
- 공룡 역할: 5종
- 자원: 최대 18종
- 제작법: 최대 20개
- 무기·도구: 최대 12개
- 생존 설비: 6개
- 부상·상태: 6개
- 주요 사건: 8개
- 탈출 엔딩: 전원 탈출, 부분 탈출, 전멸·시간 초과의 3종

콘텐츠 수는 최소 완성 기준이 아니라 상한이다. 핵심 루프가 재미없으면 종류를 늘리지 않고 시스템을 수정한다.

### 6.3 엔딩 판정

엔딩은 7일 차 계곡 붕괴 마감 또는 모든 생존 참가자의 탈출이 확정되는 순간 판정한다.

- 전원 탈출: 세션에 참가한 플레이어 모두가 균열에 진입함
- 부분 탈출: 최소 1명이 진입했지만 다른 참가자가 사망, 미복귀 연결 종료 또는 계곡 잔류 상태임
- 전멸·시간 초과: 아무도 균열에 진입하지 못함

싱글플레이에는 전원 탈출과 전멸·시간 초과만 존재한다. 협동에서 연결이 끊긴 플레이어가 120초 재접속 슬롯 만료 후에도 돌아오지 않으면 해당 참가자는 `미복귀 연결 종료`로 확정되며, 다른 플레이어가 탈출하더라도 부분 탈출로 판정한다. 엔딩 판정 결과에는 참가자별 `탈출`, `사망`, `잔류`, `연결 종료` 상태를 함께 저장한다.

## 7. 멀티플레이 설계

### 7.1 접속 구조

- Steam 친구 초대 기반 비공개 로비
- 1명이 호스트가 되는 호스트 권한형 P2P
- 출시 시 최대 2명
- 전용 서버 없음
- 자체 음성 채팅 없음
- 외부 음성 없이도 위험, 아이템, 이동, 대기, 공격 핑으로 완주 가능

Steam의 최신 네트워크 API와 릴레이를 사용해 상대방의 실제 IP를 노출하지 않는다. 로비와 패킷 전송은 별개로 취급하며, 로비 참가자만 세션 연결을 승인한다.

### 7.2 권한과 동기화

호스트가 다음 상태의 최종 권한을 가진다.

- 시간, 날씨와 월드 시드
- 공룡 AI와 피해 판정
- 아이템 생성, 이동, 소비
- 제작 결과와 인벤토리
- 냄새·소리 이벤트
- 구조 신호기와 승패

클라이언트는 이동·상호작용·공격 의도를 전송한다. 호스트는 거리, 쿨다운, 소유권, 재료와 현재 상태를 검증한 뒤 결과를 복제한다.

- 이동·방향: 비신뢰 최신값 전송
- 인벤토리·피해·제작·퀘스트: 신뢰 전송
- 월드 스냅샷: 주기적 전송
- 공룡 원거리 상태: 낮은 빈도로 전송

### 7.3 연결 실패와 이탈

- 연결 실패: 원인별 메시지와 싱글플레이 복귀 선택 제공
- 일시 끊김: 동일 Steam 계정에 120초 재접속 슬롯 유지
- 클라이언트 이탈: 캐릭터는 안전 행동 없이 제자리에 남고, 30초 뒤 월드에서 제거
- 호스트 이탈: 마지막 안전 저장 후 세션 종료; 호스트 이전은 출시 범위에서 제외
- 버전 불일치: 접속 전 차단하고 양쪽 빌드 번호 표시

### 7.4 네트워크 보안

- 클라이언트가 보낸 피해량, 아이템 수량, 좌표를 그대로 신뢰하지 않음
- RPC마다 허용 발신자, 호출 빈도, 최대 페이로드 검사
- 문자열과 사용자 이름 길이 제한 및 UI 이스케이프
- 로비 구성원이 아닌 Steam 계정 패킷 폐기
- 임의 객체 역직렬화 금지; 명시적 스키마만 허용
- 비정상 호출은 연결별 구조화 로그에 기록하고 반복 시 연결 종료
- IP 주소와 인증 토큰을 로그나 크래시 리포트에 저장하지 않음

게임이 협동형이라도 실수나 변조가 상대방의 저장 데이터를 오염시키지 않도록 동일한 검증을 적용한다.

## 8. 저장과 데이터

### 8.1 저장 원칙

- 호스트가 세션 저장본 소유
- 월드 시드, 날짜, 시간, 날씨, 플레이어, 개체 요약, 아이템과 목표 상태 저장
- 임시 파일 작성 후 교체하는 원자적 저장
- 최신 저장 1개와 직전 정상 저장 1개 유지
- 저장 스키마 버전 포함
- 로드 실패 시 백업 복원 제안, 원본 자동 삭제 금지

### 8.2 저장 시점

- 하루 시작
- 신호기 부품 회수
- 플레이어 정상 종료
- 최종 탈출 시작 직전

위기 중 강제 종료로 결과를 무한히 되돌리는 것을 완전히 방지하지 않는다. 경쟁 게임이 아니므로 복잡한 부정행위 방지보다 저장 안정성을 우선한다.

## 9. 기술 설계

### 9.1 기술 선택

- 엔진: Godot 4.7 안정 버전 계열, 프로젝트 시작 시 최신 패치로 고정
- 언어: GDScript
- 렌더링: Godot 2D, 아이소메트릭 타일과 Y 정렬
- 네트워크: Steam 로비 + 최신 Steam P2P/Networking Messages 계열을 어댑터 뒤에 캡슐화
- 배포: Windows x86_64 Steam 빌드
- 버전 관리: Git, 대용량 원본 에셋은 별도 관리 정책 수립

개발 도중 엔진의 새 메이저·마이너 버전으로 자동 업그레이드하지 않는다. 패치 업그레이드도 별도 브랜치에서 저장·네트워크·내보내기 회귀 테스트 후 반영한다.

### 9.2 주요 모듈 경계

| 모듈 | 책임 | 직접 의존 대상 |
|---|---|---|
| Session | 날짜, 승패, 시드, 세션 상태 | World, Save, Network |
| World | 맵 구역, 활성 범위, 자원 스폰 | SimulationData |
| Survival | 수치, 부상, 치료, 사망 | Item, EventBus |
| Senses | 소리·냄새 생성과 감쇠 | WorldGrid, Weather |
| Creature | 공룡 상태와 행동 결정 | Senses, Navigation |
| Combat | 공격, 피격, 함정 검증 | Survival, Item |
| Inventory | 소유권, 이동, 소비 | ItemData |
| Crafting | 제작법과 재료 검증 | Inventory, RecipeData |
| Network | 전송, 권한, 재접속 | SteamAdapter |
| Save | 버전형 직렬화와 복구 | SessionSnapshot |
| UI | 표시와 사용자 입력 변환 | 읽기 전용 상태 모델 |

게임 규칙은 장면 노드에 흩어놓지 않는다. 공룡, 아이템, 제작법, 소리와 냄새 수치는 데이터 리소스로 정의하고, UI 설명도 동일 데이터에서 생성한다.

### 9.3 상태 흐름

```text
사용자 입력
  → 클라이언트 명령 생성
  → 호스트 권한 검증
  → 월드/생존/인벤토리 상태 변경
  → 도메인 이벤트 생성
  → 네트워크 복제 + UI/음향/애니메이션 반영
  → 안전 시점 스냅샷 저장
```

싱글플레이도 별도 규칙 코드를 만들지 않고 로컬 호스트 한 명인 동일 흐름을 사용한다.

## 10. 화면과 조작

### 10.1 기본 화면

- 중앙: 아이소메트릭 월드
- 좌측 하단: 체온, 수분, 포만, 피로의 상태 단계
- 우측 하단: 손 장비와 퀵슬롯
- 상단: 날짜, 시간, 날씨, 바람 방향
- 캐릭터 주변: 상호작용 대상, 동료 핑, 위험 징후

수치를 항상 숫자로 노출하기보다 `안정/주의/위험` 단계와 캐릭터 애니메이션을 함께 사용한다. 상세 화면에서는 정확한 원인과 효과를 확인할 수 있다.

### 10.2 입력

- 키보드·마우스 완전 지원
- 게임패드 완전 지원은 출시 기준
- 모든 행동은 재지정 가능
- 길게 누르기 시간 조절
- 토글 달리기·웅크리기 제공

## 11. 시각·음향 방향

### 11.1 시각

- 저채도 자연색과 제한적인 현대 장비의 인공색 대비
- 공룡 전체를 항상 보여주지 않고 풀, 그림자, 발자국으로 먼저 암시
- 고어는 실루엣과 혈흔 중심이며 상세 내장 표현은 제외
- 핵심 상호작용 대상은 색뿐 아니라 형태와 외곽선으로 구분

### 11.2 음향

- 방향성 발소리, 울음, 수풀 소리가 탐지 정보로 작동
- 중요 음향에는 화면 가장자리 방향 표시와 선택 자막 제공
- 공룡 종류를 오직 소리로만 판별하도록 강제하지 않음
- 음악은 탐험 중 절제하고 감지·추격 전환을 환경음으로 먼저 전달

## 12. 접근성 및 현지화

- 한국어와 영어 동시 출시
- UI 구조는 독일어·프랑스어 확장을 고려해 문자열 길이 여유 확보
- 중요 음향 자막과 방향 표시
- 색각 모드 및 색 외 형태 구분
- 화면 흔들림, 섬광, 혈흔 강도 조절
- 추격 시 카메라 확대 효과 끄기
- 게임 속도 0.75배 선택 가능; Steam 도전과제 제한 없음
- 키보드·마우스 및 게임패드 재지정
- 마이크 없이 모든 기능 사용 가능

## 13. 오류 처리와 관측성

- 개발 빌드: AI 상태, 감지 대상, 소음 반경, 냄새 격자, 네트워크 권한과 히트박스 시각화
- 출시 빌드: 개인 정보가 없는 순환형 로컬 로그 유지
- 저장, 네트워크, 리소스 로드 실패는 오류 코드와 사용자 행동을 함께 안내
- 누락된 데이터 리소스는 조용히 기본값으로 대체하지 않고 개발 빌드에서 즉시 실패
- 출시 빌드에서 치명적 콘텐츠 누락 시 해당 세션 시작을 막고 무결성 확인 안내

외부 분석 수집은 출시 필수 기능이 아니다. 도입할 경우 별도 동의, 수집 항목 문서화와 개인정보 검토를 먼저 수행한다.

- 인벤토리 무게·슬롯·소유권 불변식
- 부상별 실제 이동·제작·공격 효과
- 바람 방향에 따른 냄새 전파와 감소
- 소리 차폐와 조사 위치 계산
- AI 상태 전환 및 대상 상실
- 호스트의 잘못된 원격 명령 거부
- 저장 후 로드 상태 동등성
- 이전 저장 스키마 마이그레이션
- 고정 시드의 7일 사건 재현

### 14.2 통합 테스트

- 싱글플레이로 시작부터 전원 탈출과 전멸·시간 초과 엔딩까지 완주
- 2인 협동으로 전원 탈출, 부분 탈출, 전멸·시간 초과 엔딩까지 완주

- 인벤토리 동시 획득, 치료와 피격 동시 발생

- 엔진 패치 후 Windows 내보내기와 Steam 오버레이

### 14.3 플레이테스트 단계

1. 회색 상자 프로토타입: 개발자가 10회 플레이해 핵심 루프 검증
2. 지인 5팀: 설명 없이 1일 차 생존 여부 관찰
3. 외부 20팀: 튜토리얼, 난이도, 평균 세션과 중단 원인 수집
4. 스트리머 소규모 테스트: 화면만 보는 시청자가 위기 원인을 이해하는지 확인

## 16. 개발 단계와 중단 기준

### 16.1 단계

| 기간 | 결과물 |
|---|---|
| 1~2주 | 이동, 상호작용, 한 방 맵, Steam 2인 접속 기술 검증 |
| 3~5주 | 소리·냄새와 랩터 1종이 작동하는 회색 상자 생존 루프 |
| 6~9주 | 부상, 인벤토리, 제작, 거점 설비와 3일 세션 |
| 10~14주 | 전체 계곡, 공룡 5종, 7일 탈출과 저장 |
| 15~18주 | 아트·음향·튜토리얼·접근성·Steam 페이지 |
| 19~22주 | 외부 테스트, 네트워크·저장 안정화, 밸런스 |
| 23~24주 | Valve 심사 여유, 출시 후보 수정과 배포 |

### 16.2 중단·축소 기준

- 2주 말까지 원격 2인 이동과 상호작용이 안정적이지 않으면 멀티플레이 기능을 더 추가하지 않고 네트워크 기반부터 수정한다.
- 5주 말까지 소리·냄새로 공룡을 예측하고 피하는 플레이가 재미없으면 콘텐츠 제작을 중단하고 핵심 감지 시스템을 재설계한다.
- 9주 말까지 3일 세션 완주가 불가능하면 자유 제작 항목과 상태 수를 줄인다.
- 14주 말까지 전체 게임 루프가 완주되지 않으면 신규 공룡·아이템 제작을 중단하고 기존 콘텐츠만 완성한다.
- 출시 6주 전부터 새 핵심 기능을 받지 않는다.
