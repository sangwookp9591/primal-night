# host+3 soak 관문 기록

기준: `docs/PRIMAL_NIGHT_GITHUB_AUDIT_AND_AGENT_LOOP.md` §10 — "host + 3, 60분 soak에서 복제, 접속 해제, 아이템 소실·복제, 장비 외형 불일치 치명 오류가 0건이다."

## 실행 환경

- 일시: 2026-07-18, 로컬 macOS (Godot 4.7.1 headless)
- 명령: `SOAK_MINUTES=60 godot --headless --path . -s scripts/net/four_player_soak_harness.gd`
- 대상 HEAD: `610184b` 직전 작업 트리 (soak 시작 시점 스크립트 기준 — 인벤 발산 `26e3c7e`·재접속 수렴 `e8cd841` 수정 포함)

## 결과 — PASS

| 항목 | 값 |
|---|---|
| 실행 시간 | 3,600.04초 (60분) |
| 주기 | 69,178 cycles |
| 검증 횟수 | 1,383,562 checks (아바타 수·위치, 인벤토리 총량 보존, 장비/외형 일치, 세션 결과, peer 누수) |
| 치명 오류 | 0건 |
| Object 증가율 | +0.7% |
| 메모리 증가율 | +2.6% (380→384MB) |

로그: 재접속 창에서 도착한 장비 의도에 대한 `_reject` 진단 경고(push_warning)가 주기적으로 출력되나, 이는 호스트가 무효 시점 요청을 거부하는 정상 방어 동작이며 검증 실패 0건.

## soak가 사전에 발견·수정시킨 결함 2건

1. 장비 확정 시 소유 클라이언트 인벤토리 미갱신 → 기계 간 총량 발산 (`26e3c7e` 수정)
2. 재접속 클라이언트에 기존 원격 아바타 미재스폰 → 수렴 실패 (`e8cd841` 수정)

## 유의

- 이 결과는 헤드리스 자동 soak이다. 문서 §10의 사람 플레이테스트 관문(5명 무설명 플레이, 협동 대화 발생 등)은 별도이며 아직 수행되지 않았다.
- 4인은 여전히 "검증된 목표"이지 출시 약속으로 홍보하지 않는다 (문서 §0-6).
- CI에는 압축 모드(SOAK_MINUTES=0.5)가 상시 실행된다.
