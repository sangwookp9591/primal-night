# 저장·이어하기·일시정지·사망 복구 검증

## 설계 결정

- `SaveService`는 Autoload가 아니라 `main.tscn`의 호스트 권위 노드다. 타이틀을
  거친 명시적 게임 시작만 저장을 활성화하므로 main을 직접 인스턴스화하는 GUT와
  headless 하네스는 기존처럼 저장 I/O가 비활성이다.
- 단일 파일은 `user://saves/slot_1.save`, 포맷은 사람이 읽을 수 있는 JSON,
  현재 `version = 1`이다. 손상 JSON, 필수 필드 누락, 버전 불일치는 main 진입 전에
  거부하고 한국어 메시지를 표시한다. 마이그레이션은 하지 않는다.
- 인벤토리는 `Inventory`의 슬롯 `{id,count}` 스냅샷, 장비는
  `EquipmentComponent.get_snapshot()`을 그대로 쓴다. 거점 보관함도
  `NetBaseCamp`가 원자적 롤백에 쓰는 동일 Inventory 슬롯 표현을 사용한다.
- 자동 저장은 `DAYLIGHT -> DUSK -> NIGHT` 중 NIGHT 진입과 NIGHT -> DAYLIGHT
  진입, 그리고 잠자리 홀드 완료 시점이다. 수동 저장은 ESC 메뉴에서만 제공한다.
- 사망 기록은 마지막 체크포인트의 `death_record` 메타데이터만 갱신한다. 죽은
  플레이어/월드로 체크포인트를 덮지 않는다. “마지막 저장에서 다시”는 체크포인트
  복원 뒤 현재 난이도의 `death_item_keep_ratio`를 한 번 적용한다.

## 저장 범위와 복원 순서

저장 범위는 난이도, 플레이어 위치, 생존 수치 4종, 체력·출혈, 인벤토리, 장비,
세션 일·시각·진행 여부, LoopObjective 결과·위험 노출·관리 이력·사망 원인,
WorldItem, 모닥불 위치·연료·점화, 보관함, 건조대 진행, 잠자리 존재,
사체 위치·해체 비트·진행, 랩터·청소동물 위치·생존 여부·간략 상태, 사망 기록이다.

복원 순서는 다음과 같다.

1. 저장 스키마와 버전 검증
2. 난이도 적용
3. 플레이어 위치·생존 수치·체력·출혈·인벤토리·장비
4. SessionClock과 LoopObjective
5. WorldItem, 모닥불, 거점 프롭, 사체
6. 랩터·청소동물 위치·생존 여부·간략 상태
7. 사망 복구라면 난이도별 아이템 유지 비율 적용

## 자동 검증 결과

- 전체 GUT: 95 scripts, 549 tests, 27,750 asserts, failures 0
- 저장 전용 GUT: 6 tests, 28 asserts, failures 0
- two_player: exit 0
- coop: exit 0
- goal_scene: exit 0
- three_day_slice: exit 0 (`THREE_DAY_SLICE_OK`)
- combat: exit 0 (`PASS`)
- soak 0.05분: exit 0, 59 cycles, 1,182 checks, PASS

GUT의 기존 12 orphan 경고와 종료 시 기존 ObjectDB/resource 경고는 남아 있으나
테스트 실패는 없다. 모든 하네스 로그에서 SaveService/slot_1 접근은 0건이라
headless 저장 비활성 경계도 확인했다.

## GUI 수동 검증 절차

1. 임시 검증이 필요하면 기존
   `~/Library/Application Support/Godot/app_userdata/PRIMAL NIGHT/saves/slot_1.save`
   를 별도 보관하고 게임을 실행한다.
2. 저장이 없을 때 타이틀의 “이어하기”가 비활성인지 확인한다.
3. 싱글 시작, 난이도 선택 후 ESC를 누른다. 세계 시각, 랩터, 감각 피드백이
   멈추는지 확인하고 “저장”, “계속”을 차례로 누른다.
4. 타이틀로 돌아가 “이어하기”가 활성인지 확인하고 선택한다. 난이도, 플레이어
   상태/위치, 인벤토리·장비, 시각, 월드 아이템, 모닥불/거점/사체/생물 상태가
   직전 체크포인트와 일치하는지 확인한다.
5. 낮/밤 경계 통과와 잠자리 사용 뒤 저장 파일 수정 시각이 갱신되는지 확인한다.
6. 플레이어를 사망시키고 기존 원인 문장과 “마지막 저장에서 다시”,
   “타이틀로”가 보이는지 확인한다. 재시작 뒤 마지막 저장 상태로 돌아오되 선택
   난이도의 아이템 유지율이 적용되는지 확인한다.
7. 저장 파일을 잘못된 JSON으로 바꾸거나 `version`을 999로 바꾼 뒤 이어하기가
   main에 진입하지 않고 각각 손상/버전 한국어 메시지를 표시하는지 확인한다.
8. 유효 저장이 있는 상태에서 “싱글 시작”을 선택하면 덮어쓰기 확인 화면이
   나오고, 취소는 저장을 보존하며 확인은 새 게임을 시작하는지 확인한다.
9. 호스트+클라이언트로 접속해 클라이언트 ESC 메뉴가 세계를 멈추지 않는지,
   호스트 종료 시 세션이 종료되고 클라이언트 저장이 생성되지 않는지 확인한다.
